# Chunk 08: Classes and Data Models

## Goal

By the end of this chunk, you will be able to:

- define a class and create an instance;
- store data in instance attributes;
- add behavior with methods;
- create a data model with `@dataclass`;
- validate a dataclass after creation.

## 1. A class describes a kind of object

A **class** is a blueprint that groups related data and behavior. An **instance** is one object created from that blueprint.

The special `__init__()` method initializes a new instance. Its first parameter, normally named `self`, refers to the instance currently being created. Assignments such as `self.name = name` create instance **attributes**.

The first example defines a `Learner` class and creates two separate instances. Each instance has its own attribute values.

Run [01_class_basics.py](examples/01_class_basics.py).

Expected output:

```text
Maya is learning functions.
Sam is learning classes.
```

Writing `Learner("Maya", "functions")` calls the class to create an instance. Python then calls its `__init__()` method automatically.

## 2. Methods add behavior

A **method** is a function defined inside a class. It uses `self` to read or change the current instance.

The next class stores a model's name and availability. Its `describe()` method uses those attributes to return a readable status. Calling `model.describe()` automatically supplies `model` as `self`.

Run [02_methods.py](examples/02_methods.py).

Expected output:

```text
small-model is available.
large-model is unavailable.
```

Do not pass `self` yourself when calling an instance method.

## 3. Dataclasses reduce repeated code

A class used mainly to hold related values is a **data model**. Python's standard-library `@dataclass` decorator can generate common methods, including `__init__()` and a readable representation.

A decorator begins with `@` and adjusts the class or function immediately below it.

The next example defines the expected fields with type hints. `@dataclass` uses those fields to create the initializer, so no manual `__init__()` is needed.

Run [03_dataclass_basics.py](examples/03_dataclass_basics.py).

Expected output:

```text
Role: user
Content: Explain dataclasses.
ChatMessage(role='user', content='Explain dataclasses.')
```

The final line comes from the useful representation generated by `@dataclass`.

## 4. Data models can contain other models

Models can be placed in lists just like strings or dictionaries. Functions can use hints such as `list[ChatMessage]` to make that structure clear.

The next example builds a list of `ChatMessage` instances and gives it to a display function. Attribute access such as `message.role` replaces dictionary access such as `message["role"]`.

Run [04_model_collection.py](examples/04_model_collection.py).

Expected output:

```text
SYSTEM: Answer clearly.
USER: What is a data model?
```

A dictionary is flexible. A data model gives the expected fields meaningful names in one reusable definition.

## 5. Dataclasses can validate themselves

After a dataclass initializes its fields, it automatically calls `__post_init__()` when that method exists. You can use it to check rules and raise an error for invalid data.

The final example checks that:

- `temperature` is between `0.0` and `1.0`;
- `max_tokens` is greater than zero.

It first creates valid settings. It then tries invalid settings and catches the resulting `ValueError`.

Run [05_model_validation.py](examples/05_model_validation.py).

Expected output:

```text
Valid temperature: 0.2
Invalid settings: temperature must be between 0.0 and 1.0
```

Manual validation becomes repetitive as models grow. Pydantic will later use type hints to perform much of this work and produce detailed validation errors.
